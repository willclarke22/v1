# V3.7D.2A.1 — Context + legacy-topic compatibility + learner-facing response

Requires successful V3.7D.2A **and** V3.7D.2A-COST installation. Does not start workers or Director, add routes, change root proxy, or modify original v1 checkout. Inherits the same exact-write approval and pinned sandbox destination gates.

- Semantic embedding query now includes assessment topic, root problem, original learner question and clarification, but **learner evidence** stays original and unchanged in preview/approved write.
- Legacy topics can be associated through stringent evidence of *topic-level* membership (semantic >= 0.82 and label fit >=0.67, or label fit 1 and semantic >=0.68, with assessed root confidence >=0.78). This creates a NEW learning-difficulty evidence entry; never assumes an existing root problem.
- A `hold` still cannot authorize a write. Unavailable/lexical-only semantic retrieval cannot trigger new-topic creation or legacy topic association.
- Assessment topic labels are prompted to be specific, reusable subject labels. The learner-facing message now uses only a direct response from `teaching_strategy`, not the hidden planning `learner_reflection` or `Next:` directive. The model prompt now explicitly requests learner-directed explanation. Frozen visual handoff still retains the full plan.
- Topic label proposed for creation is visible in Workbench, but remains generated by Model A and is **not editable** in this patch. Reassess if label is unsuitable. No DB-wide uniqueness guarantee was added.
- Previous cost observability remains unchanged.

Installation makes **no database changes**; actual writes still require the explicit Workbench approval. Rollback restores **source only**, not previously approved DB changes.

If the cost observability patch has not been installed, run that patch first using its installer, then return to this ZIP.
