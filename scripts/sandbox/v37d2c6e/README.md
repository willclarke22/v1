# MyWay V3.7D.2C.6E — Protected Cloud Semantic Retrieval (Read-Only Pilot)

## Purpose and completed boundaries
- An optional cloud Workbench **protected pgvector search panel**. The user signs in with existing sandbox Supabase Auth and initiates a synthetic query. Browser MiniLM creates a normalized 384-dimensional vector; the browser sends it to a restricted, owner-scoped Supabase RPC. Only topic IDs, labels, model IDs, and similarity scores return. No raw stored vectors, learner messages, original source tables, write endpoints, or credentials are exposed.
- A **new, independent cloud vector projection** populated from `topic_vectors` *label* centroids, synced from the existing sandbox source, with a separate **optional** SQL Cron job. No edits to original topic_state, topic_vectors, owner binding, D2C5C job, or public cloud snapshot policies.
- A read-only catalog of available source model identities, browser-vs-stored ranking comparison on up to 200 *label-only* examples, and model-load/inference/RPC/total latency measurements. The protected server search itself has **no 200-topic cap** and returns up to 20 ranked matches, scanning a bounded 5,000-topic index exactly (no HNSW).

## Important limits
- This is a **pilot**, not permission to use cross-model similarities to create or associate topics. The local embedder may record a vague `local-embedding-service` identity while browser MiniLM reports `Xenova/all-MiniLM-L6-v2`. Identical embedding dimension alone **DOES NOT** prove compatibility. Backend q8 quantization can also differ. All results are advisory until tested with a labeled evaluation set against local Python results.
- The projection contains **label vectors only**. Historical root-problem embeddings and equivalence require separate modeling, privacy review, and tests. No cloud Model A/B/C, cloud topic writes, or automatic associations are enabled here.
- User types synthetic queries into diagnostic. Browser vector is sent **only** to the private authenticated Supabase RPC, not to the MyWay Next.js server. Browser loads Transformers.js/weights from third parties on first use. No per-token model API charge; database and bandwidth costs are not priced.
- The cloud panel remains under `/sandbox/probe-lab/learning-space/workbench`; no Supabase SQL is auto-executed by local patch installer or by Vercel deployment. Cloud API routes remain blocked.

## Installation order
1. **STOP** local Next.js server. Unzip package to Downloads. Run `INSTALL_V37D2C6E.ps1` in PowerShell. It verifies branch, original main, committed clean baseline, 6D release marker/ledger, current source hashes and TypeScript/JS contracts. It never commits/pushes, executes SQL, or starts Cron. Rollback on verification failure. No hard-coded current experimental Git SHA; uses source hash + safety invariants.
2. Review the generated changes (`git status --short`, `git diff --stat`, `git diff --check`), run the new guarded launcher locally, and only then commit/push **experimental branch**. Do not use `git add -A`.
3. In **Supabase `myway_sandbox` only**, use the SQL Editor to run `sql/00_PREFLIGHT.sql` (read-only). Confirm *single owner*, source and snapshot counts, pgvector installed in `extensions`, and model distribution. Next manually run `sql/01_INSTALL_VECTOR_PROJECTION.sql`, then `sql/02_RUN_ONE_REFRESH.sql` and `sql/04_VERIFY_SECURITY.sql`. Verify: one owner; RLS true and FORCE true; **zero table grants** to anon/authenticated; anon RPC EXECUTE false and authenticated EXECUTE true.
4. In the **experimental Vercel Workbench**, sign in with the sandbox test account, click **Load protected vector catalog**, then search a synthetic question. Confirm expected model labels, top matches, browser/sample overlap, latency, and sign-out denial. This is a diagnostic, not topic-memory decision authority. If SQL is not installed, the panel displays unavailable and other cloud features continue.
5. **Only after** the manual read-only test succeeds, optionally run `sql/03_ENABLE_CRON.sql` in **myway_sandbox**. Check `cron.job_run_details` and `sql/04_VERIFY_SECURITY.sql`. It is a separate job named `myway_cloud_vectors_v37d2c6e` every minute; original `myway_cloud_sync_v37d2c5c` remains untouched. If an error occurs use `sql/05_STOP_CRON.sql`; if you want to remove vector projection entirely stop Cron first, then `sql/06_REMOVE_VECTOR_PROJECTION.sql`.
6. To undo **local source-only** changes *before committing 6E*, run `ROLLBACK_V37D2C6E.ps1`. This never runs SQL.

## Verifications and decision criteria
- Syntax and source-integrity checks, exact manifest allowlist, ancestor hash ledgers, old 6D quality regression and new 6E offline test. No live SQL execution or browser model downloads can be tested in the package-building environment.
- Run a **label-quality benchmark** with at least 10 synthetic known-topic queries: record whether top-1/top-5 match expected topics, browser/pgvector agreement, and response latency. Reject claims of model equivalence until compared against identical text embedded by *both* Python SentenceTransformer and browser WASM/WebGPU (cosine/similarities with calibrated thresholds). The old 200-label browser panel remains as an independent comparator.
- **Cost clarity:** browser inference has no per-token API bill, but compute/bandwidth and Supabase database usage may cost money. OpenAI/GLM real-turn cost estimation remains in 6D, unchanged.

## Security notes
- Cloud RPC is `SECURITY DEFINER` but it pins `search_path=''`, validates `auth.uid()` and `auth.role()`, enforces the owner in the existing **private** D2C5C singleton binding, joins only matching owner snapshots, bounds query dimensions/length and return size, and revokes default public/anon EXECUTE. The physical vector projection has FORCE RLS and **no browser SELECT grant or RLS policy**. Do not add broad GRANTs.
- `myway_sync_private.refresh_cloud_vector_snapshot_v37d2c6e()` is admin-only and in a schema not exposed through the Data API. It shares the advisory lock with the existing 5C Cron sync and rejects unexpected owner/row counts. The SQL editor runs with privilege; ensure correct project before execution.
- Supabase Postgres `extensions.vector` schema is assumed; the SQL preflight intentionally fails if the project differs. Test signed-out RPC and browser access manually; SQL-editor rights do not simulate an authenticated browser.

## SQL source hotfix (6E-SQL-FIX1, November 2026)
- The initial version of `01_INSTALL_VECTOR_PROJECTION.sql` compared raw `extensions.vector` values with `IS DISTINCT FROM`, which raises PostgreSQL error 42883 because pgvector does not supply vector equality. This source revision compares `embedding::text` only within the private synchronization function's `ON CONFLICT` predicate.
- If the database was already installed, **do not rerun `01_INSTALL_VECTOR_PROJECTION.sql`**. The corresponding one-time `MyWay_V37D2C6E_Vector_Refresh_SQL_HOTFIX1.sql` was manually executed in `myway_sandbox`; this source patch records that fix in Git and adds a regression assertion.
- This ZIP never executes SQL, enables Cron, grants browser writes or alters the original project.
